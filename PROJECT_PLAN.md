# Your Track to Health: migration plan

This is the working plan for migrating every page of yourtracktohealth.com into the redesign. It follows the design PDFs and takes the content from the current pages.

**Keep this plan current.**
- When you start a task, tick it in progress; when you finish it, tick it done.
- Add new tasks as they come up.
- Record each work session in the progress log at the end.
- Decisions and open questions live in `PROJECT_OVERVIEW.md`; this file links to them.

Status: `[x]` done · `[~]` in progress · `[ ]` to do · `[?]` needs a decision from the site owner

## The current site in numbers

Figures from `migration-work/site-inventory.json`:
- **178 HTML pages**, about 50,000 words.
- **334 linked PDFs**, with 1,501 links to them.
- **40 pages** in the main nav and 158 in the site map.
- **1 login-gated link**.
- All pages are server-rendered ASP.NET, identified by query string (`Content.aspx?MenuId=N`).

| Template on the current site | Pages | Planned target in the redesign |

## Phase 2: catalog and URL map

- [x] Group the pages into templates. The 19 page types in the table above come from the inventory crawl. Phase 4 refines each one into a page template with its block mapping.
- [x] Build the URL map, generated by `migration-work/url-map/build-url-map.cjs`. Outputs:
  - `url-map.json` and `url-map.csv`: old URL, aliases, new path, action (page / merge / pdf / new / done / external / none), template, notes
  - `redirects.csv`: 257 draft CDN redirect rules (path + query → new path or PDF)
  - `check-targets.cjs`: checks that every internal link in the designs points at a page in the map (35 targets, 0 missing)
- [x] Results: 158 pages migrate as pages. 5 merge into another page. 12 PDF-only pages redirect to their PDF. 6 new pages have no single source:
  - CHCB and HDHP plan pages
  - the savings & spending accounts landing
  - fitness memberships
  - New hire
  - search

  - The two "Railroad Healthlink" pages have the same content and are merged.

  - The generic page "We're always working to serve you better" is the feedback form's thank-you page.
- [x] Owner review of the open mapping points (2026-11-10):

## Phase 3: blocks the designs don't cover

Built 2026-11-10. These derive from the existing tokens and are documented in `PROJECT_BLOCKS.md` and `PROJECT_DESIGN_SYSTEM.md`. All of them are on the test page `/drafts/phase3-blocks.html`, which uses real current-site content. They were checked at 1440, 1024 and 425 px with no overflow and no script errors.

- [x] **Page hero for inner pages:** `hero (navy)` with the section name as eyebrow and an optional intro sentence. On `content` and `article` pages the title runs up to 860 px wide.
- [x] **Long-form default content:** images, image captions, blockquotes, nested lists and teal bullets. On pages with the `content` or `article` template, text and tables keep an 860 px width.
- [x] **Table** (`table`): navy header row, zebra rows, rounded card. Tables with 4 or more columns scroll sideways on phones. Variants: `no-header`, `compact`.
- [x] **Document list** (`documents`): PDF icon, title, file-type tag and optional description; heading rows group the documents.
- [x] **Video** (`videos`): thumbnail cards with a play button that open the video in a new tab, plus a transcript link.
- [x] **Infographic article:** no new block. The importer writes the image plus a link list made from the image-map areas, and long-form styles cover it (Phase 4).
- [x] **Section menu** (`section-nav`, revised 2026-11-11): reads the `/fragments/section-nav` tree.
  - Desktop: sticky left column. Smaller screens: collapsible bar.
  - The current branch is open, with "On this page" jump links and the hero eyebrow linking to the section.
  - Replaces the old side menu, breadcrumbs, "Resources for" and "Jump to".
- [x] **Footer:** added News, Video library, Site map and Accessibility (the old footer's utility links).
- [x] **Article list** (`article-list`): built from the page index. Takes a folder and a limit; newest first; "Show more" button.
- [x] **Search** (`search`): reads `?q=`, scores title, description and path, highlights the matches.
- [x] **Contact directory:** no new block. It reuses `benefit-cards` (logo, phone, hours) and `accordion` for the service topics.
- [x] **Phone numbers:** auto-linked as `tel:` in default content (`scripts/scripts.js` → `linkPhoneNumbers`).
- [x] **External and PDF links:** open in a new tab, with a trailing icon and screen-reader text (`decorateLinkTypes`).
- [x] **404 page** in the new design (`404.html`): navy header, search field, homepage link and a "Go back" button.
- [x] **FSA calculator** (`fsa-calculator`): the same formula as `FSAcalculator.aspx` (verified with the same inputs). The maximum contribution and the RRTA and Medicare rates are authorable.
- [x] **Benefit lookup** (`benefit-lookup`): railroad → union → ZIP form, plan option cards and SBC links. It reads a spreadsheet with `railroads`, `unions` and `options` sheets. The 48 railroads are taken from the current form; the test data in `/drafts/benefit-lookup-sample.json` carries clearly marked sample unions and options.
- [ ] **Lookup data:** the owner exports the real union and option data (railroad × union × ZIP → administrator, plan and SBC PDF) into the lookup spreadsheet in DA. The current form loads unions per railroad through a server round trip, and the results depend on the ZIP, so the data can't be scraped reliably.
- [ ] **FSA values:** the owner confirms the current maximum contribution (the current site still uses $3,500 with plan year 2019) and the tax rates.
- [ ] **Webmaster feedback form:** rebuild the feedback box and its thank-you page. Waiting for the owner to choose a form backend.
- [ ] **Page index:** configure the query index (Phase 7) with the columns `title`, `description`, `date`, `navTitle` and `lastModified`. Search, the article list and "In this section" read it.

## Phase 4: import infrastructure

Done 2026-11-11. Details are in `PROJECT_CONTENT_IMPORT.md` §3.

- [x] One import script for every current page type (`tools/importer/import-site.js`). It takes paths, titles and sections from the URL map (`url-map-data.js`, generated by `build-url-map.cjs`).
- [x] Cleanup: banner, side menu, breadcrumbs, print button, decorative images, icon-font glyphs, inline styles.
- [x] Hub pages whose H1 was injected by script: the title comes from the URL map; the old "Your Track To Health -" prefix is removed.
- [x] Parsers:
  - icon card grids → `Cards (resource)`
  - collapsible panels, including nested ones → `Accordion (closed)`
  - definition lists → paragraphs
  - data tables → `Table`
  - PDF heading lists → `Documents`
  - video library → `Videos`
  - image maps → image plus "Related links"
  - archives → `Article list`
  - tools → `Benefit lookup` and `Fsa calculator`
- [x] Link rewriting:
  - old `.aspx` → new paths
  - `ContactUs.aspx?Service=…` → `/contact-forms`
  - PDF-only pages → their PDF
- [x] **Finding: the old server serves PDFs only through its viewer page.** Direct `/PDF_Files/…` addresses return 404. Every PDF link (imported pages, nav, footer, homepage, redirects) now uses `https://www.yourtracktohealth.com/Common/PDFViewer.aspx?fileName=/PDF_Files/…`. The site code recognizes these as PDF links.
- [x] Headings and page titles in sentence case, keeping plan, program and brand names (`KEEP_PHRASES`, `KEEP_CAPS`).
- [x] Every inner page ends with an empty "In this section" block and carries Metadata (Title, Description, Template).
- [x] Merge sources are imported to `/drafts/merge-sources/…`. `tools/importer/merge-pages.cjs` merges 24/7 Telemedicine into 24/7 nurses & telemedicine; run it after every import.
- [x] Pilot import of one page per type, with fixes, before the full run.
