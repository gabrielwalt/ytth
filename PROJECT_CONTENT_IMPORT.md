# Your Track to Health: content and import

Page content is generated into `content/<path>.plain.html` by import scripts. The local preview renders from there. Don't hand-write whole pages in `content/`. Small fixes can be edited in a `.plain.html` file directly, but the next import run overwrites them, so carry them into the source as well.

## 1. Pages from the designs (done)

The pages whose content comes from the PDFs are first written down as semantic HTML in `migration-work/design-source/`. Each file is a transcription of a PDF page, using the PDF's copy and the block structure from `PROJECT_BLOCKS.md`.

| Source | Document path |
|---|---|
| `nav.html` | `/nav` |
| `footer.html` | `/footer` |
| `home.html` | `/index` |
| `benefits-coverage.html` | `/benefits-coverage` |
| `mmcp.html` | `/benefits-coverage/medical-plans/mmcp` |
| `section-nav.html` (generated by `build-section-nav.cjs`) | `/fragments/section-nav` |
| `sitemap.html` (generated by `build-sitemap.cjs`) | `/sitemap` |
| `video-library.html` (generated, see "Video library" below) | `/video-library` |
| the new pages listed at the end of §3 | their paths |

Source conventions:
- `<meta name="target-path">` sets the document path. `<title>` and `<meta name="description">` become the page Metadata (except on nav and footer).
- Each `<section>` becomes a section. Its `class` becomes the Section Metadata "Style", for example `class="hexagons shaded medium"`.
- `<div data-block="Name (variant)">` becomes a block table. Its child `div`s are rows, and their child `div`s are cells.
- Write icons as `:name:` text. A link that holds only an icon is dropped on import, so give it visible text (the header and footer turn that text into the accessible name).
- When a table cell mixes text with `<sup>`, wrap the cell in `<p>`. Otherwise the import splits it.
- Images point at `/migration-work/assets/…`:
  - `photos/`: hero and card photos
  - `partners/2x/`: partner logos at twice their display size

The importer:
- `tools/importer/import-design.js` handles icons, block tables, metadata and section breaks. It uses `parsers/design-block.js`.
- It is bundled into `import-design.bundle.js` with the content-import skill's `aem-import-bundle.sh`.
- It runs with the skill's `run-bulk-import.js --import-script tools/importer/import-design.bundle.js --urls tools/importer/urls-design-<page>.txt --force`.
- The URL lists:
  - `urls-design.txt`: nav, footer and home
  - `urls-design-benefits.txt`
  - `urls-design-mmcp.txt`
  - `urls-design-home.txt`
  - `urls-design-nav.txt`: nav, footer, section menu and site map
  - `urls-design-new.txt`: the new pages
  - `urls-design-test.txt`: the author-combinations test page (`author-combinations.html` → `/drafts/author-combinations`)
  - `urls-design-videos.txt`: the video library
- Reports go to `tools/importer/reports/`.

### Video library (since 2026-11-11)

`/video-library` comes from the design route, not from the site importer, so it can carry the in-page players and HTML transcripts. Everything is in `migration-work/videos/`:
- `inventory.json`: every video of the current site (library and other pages): title, Brightcove account/player/video id and where each id comes from (`unknown` when it can't be established), caption tracks, transcript PDF (checked: 200, a real PDF), old and new pages.
- `convert-transcripts.mjs`: turns each transcript PDF into `transcripts/<id>.html` (verbatim: one paragraph per PDF paragraph, speaker labels bold, scene descriptions italic, on-screen text lines kept) and `transcripts/<id>.pdf.txt` (the PDF text). It needs `pdfjs-dist`, which is not a project dependency: install it in a temp folder and pass its `legacy/build/pdf.mjs`. Download the PDFs through the viewer address, each into its own folder (`<root>/<PDF name>/transcript.pdf`).
- `build-video-library.cjs`: writes `design-source/video-library.html` from the inventory and the transcripts (one `Videos` block per group of the old page, sentence-case titles, the Brightcove posters in `migration-work/assets/videos/`).
- `check-transcripts.cjs`: compares each transcript on the imported page with its PDF text, word by word (all 15 at 100% on 2026-11-11).

Run: `node migration-work/videos/build-video-library.cjs`, then the design import with `urls-design-videos.txt`, then `node migration-work/videos/check-transcripts.cjs`. `VideoLibrary.aspx` must not be re-imported with the site importer (it would bring back the old cards).

## 2. URL map and redirects

`migration-work/url-map/build-url-map.cjs` builds the map from the site inventory. It applies the section rules and the explicit overrides it lists, then writes:
- `url-map.json` / `url-map.csv`: one row per old page (plus new pages without a source). Each row has its action:
  - `page`: migrate as a page
  - `merge`: the content goes into another page and the old URL redirects
  - `pdf`: no page, redirect to the PDF
  - `new`: a page with no single source
  - `done`: built from the designs
  - `external`: no page; the address stays an external link
  - `none`: no page; redirect only
- `redirects.csv`: CDN rules (old path + query → target). The owner's IT team applies them.

Regenerate the map after every change to its rules. Run `check-targets.cjs` to confirm that every internal link in the designs has a page. Importers rewrite old links with `url-map.json`.

## 3. Pages from the current site (imported 2026-11-11)

`tools/importer/import-site.js` handles every page type of the current site. It is bundled into `import-site.bundle.js`. It runs with `run-bulk-import.js --import-script tools/importer/import-site.bundle.js --urls tools/importer/urls-site.txt --force` (163 URLs: every `page` and `merge` row of the URL map; `urls-site-pilot.txt` has one page per type).

What it does on each page:
- **Path, title and section** come from `tools/importer/url-map-data.js`, which `build-url-map.cjs` generates. A page missing from the map fails loudly.
- **Removes:** the old banner, side menu, breadcrumbs, print button, skip links, decorative arrow/external/print images, icon-font glyphs and inline styles.
- **Page header:** `Hero (navy)` with the section as eyebrow (Benefits & coverage, Health programs, Retirement, Contact & forms, News) and the H1 in sentence case. The intro is the old H2 subtitle or the sentence after the title in the old banner's alt text; it is removed from the body if it repeats there. A subtitle that ends with a colon ("Please choose from the following:") introduces the list below it, so it opens the content instead of the header (Contact us, Contact UnitedHealthcare, FSA FAQ).
- **Content patterns:**
  - icon card grids (`.contentbox`) and sibling icon columns → `Cards (resource)`; each tile keeps its icon: the old icon-font class is mapped to the hexagon library (`ICONS` in the script, `migration-work/icons/icon-map.json`) and written as a `:hex-…:` paragraph
  - a page whose content starts at h3 (no h2) gets its headings moved up one level
  - the Contact Us side box "Website feedback & technical issues?" follows the content (only boxes outside the content column)
  - collapsible panels (`.content-panel-default`) → `Accordion (closed)`
  - `<dl>` → paragraphs with bold terms
  - data tables → `Table` (or `Table (no-header)`); layout tables are flattened
  - heading links to PDFs plus their descriptions → `Documents`
  - the video library → `Videos` per group (superseded: the page now comes from `design-source/video-library.html`, see §1)
  - image maps → the image (alt text = page title + "infographic") followed by a "Related links" list
  - archives → `Article list`
  - the two tools → `Benefit lookup` (data sheet `/benefits-coverage/benefit-lookup-data.json`) and `Fsa calculator`
- **Text:** loose text and double `<br>` become paragraphs. Bold spans become `<strong>`. Phone spans become plain text (the site links phone numbers automatically).
- **Calls to action:** short single-link paragraphs with action words become primary buttons.
- **Headings** get sentence case. Known plan, program and brand names are kept as written (`KEEP_PHRASES`, `KEEP_CAPS`).
- **Links:**
  - old `.aspx` URLs become new paths through the URL map
  - links to PDF-only pages point to their PDF
  - unknown old URLs stay absolute on the old site
- **PDFs:** **all PDF links use the old server's viewer address** `https://www.yourtracktohealth.com/Common/PDFViewer.aspx?fileName=/PDF_Files/…`. Direct `/PDF_Files/…` URLs return 404 on the current server. The final PDF host is one setting (`PDF_HOST` in `build-url-map.cjs`).
- **Page ending:** every page ends with an empty `Section nav` block, plus Section Metadata `narrow` and Metadata (Title, Description, Template `content` or `article`).
- **Merge sources** (content that belongs in another page) are imported to `/drafts/merge-sources/…`, so no content is lost; they are combined by hand.

Before an import that follows an importer change, run the importer tests: `node --test tools/importer/test/*.test.mjs` (the Contact & forms panels, from the unmodified old page in `test/fixtures/`).

After every import:
1. Run `node tools/importer/merge-pages.cjs` (merges 24/7 Telemedicine into the 24/7 nurses & telemedicine page).
1. Run `node tools/importer/apply-fragments.cjs` (replaces the shared content with fragment references; the fragment documents come from `design-source/fragment-*.html` via `urls-design-fragments.txt`; consumers go to `tools/importer/fragments-report.json`). Only word-for-word identical content is replaced; anything else is listed as "NOT replaced".
2. Run `node migration-work/url-map/check-content.cjs` (missing pages, broken internal links, links left on the old site).
3. Run `node migration-work/url-map/build-search-index.cjs`. It refreshes `/search-index.json` (pages with their text, the page index search uses until the query index exists) and `/search-documents.json` (the PDFs linked from the pages, which search always uses).
4. When pages were added or renamed, regenerate the section menu with `node migration-work/url-map/build-section-nav.cjs` and then the site map with `node migration-work/url-map/build-sitemap.cjs`. Import both with the design importer (`--urls tools/importer/urls-design-nav.txt`, which also re-imports nav and footer). After launch they are maintained in DA (`/fragments/section-nav`, `/sitemap`).
   - The section menu's order follows the header groups in `design-source/nav.html`; pages that belong under another page than their folder (`PARENTS`, e.g. the prediabetes pages under Prediabetes & diabetes) are set in the script.
5. Run `node migration-work/url-map/check-navigation.cjs`: which pages the header, footer and section menu reach, which are only linked from content, and which are linked from nowhere.

Pages with no single source are design-source pages too:
- `chcb.html` and `hdhp.html`: MMCP layout, from the "How the plan works: at a glance" tables. The HDHP explainer and FAQ are merged in.
- `heart-health.html`: from the Railroad Heart Health Guide PDF.
- `fitness-memberships.html`: from the One Pass Select flyer.
- `savings-spending-accounts.html`
- `find-a-doctor.html`: the provider directories of Aetna, Highmark and UnitedHealthcare.
- `new-hire.html`: placeholder.
- `search.html`

These are imported with `urls-design-new.txt`.

## Checks and research scripts

| Script | What it does |
|---|---|
| `migration-work/url-map/check-targets.cjs` | Every internal link in the design sources has a page |
| `migration-work/url-map/check-content.cjs` | Missing pages, broken internal links, links left on the old site |
| `migration-work/url-map/check-navigation.cjs` | Which pages the header, footer and section menu reach; orphans |
| `migration-work/qa/measure-alignment.js` + `sweep-report.cjs` | Block edges of every page against the content frame, per breakpoint (run in a Playwright browser session; the report lists only near-misses) |
| `migration-work/research/old-search.cjs` | Runs one search on the current site (`SiteSearch.aspx`) and saves the result page |
| `migration-work/research/old-lookup.cjs` | Runs the current benefit lookup for one railroad and a few ZIP codes (`parse-lookup.cjs` prints the results) |

The research scripts write to `/tmp/ytth-research/` and send a handful of requests to the current site; keep them to occasional use.

## Local preview, DA, preview and live

- The local preview serves documents under `/content/<path>`. It doesn't convert Section Metadata, Metadata or `:icon:` text; `scripts/scripts.js` does that in the browser so the preview matches the live pipeline.
- The site's content source is the DA location in the site configuration (`https://content.da.live/gabrielwalt/ytth/`).
- Uploads to DA, previews and publishes happen only on an explicit request. Before uploading a page, make sure `content/<path>.plain.html` holds exactly what is being uploaded.
